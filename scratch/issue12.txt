# feat(api): Build Decoupled GitHub Integration Pipeline with Native Caching & Fallbacks

## Context & Objective
We need to display live GitHub stats (stars, forks, open issues, language demographics, recent commits) in our portfolio showcase cards without hitting rate limits (60/hour unauthenticated) or introducing blockages in SSR page load times.

---

## 📋 Architecture & Implementation Details
* **Decoupled API Client (`lib/github.ts`):** 
  - Standardized custom URL parsing (`parseGitHubUrl`) to extract owner and repository dynamically from database strings.
  - Implemented rate-limit authentication support via `process.env.GITHUB_TOKEN`.
* **Hybrid Cache Topology:**
  - Standard Server Context: Wrapped statistics calls inside Next.js `unstable_cache` with a 3600-second (1 hour) TTL, tagged under `"github"`.
  - Non-App Contexts: Implemented graceful try/catch blocks that capture standard Next.js incremental cache errors and fall back automatically to direct raw HTTP fetches (essential for seed scripts, static builds, and CLI migrations running outside Next.js server threads).
* **Robust Fail-Safes:**
  - Development warnings if no `GITHUB_TOKEN` is found.
  - Non-blocking error handling: failed API endpoints return `null` instead of raising page-level build or rendering exceptions.
