# feat(ui-ux): Develop Dynamic "Shrink-Wrap" Bento Grid for GitHub Stats & Language Demographics

## Context & Objective
We need a visually stunning way to present the aggregated data from the GitHub API (commits, Rust vs. TS vs. Python loc counts). Standard CSS Grid leaves awkward white space. We will use the Aceternity Bento Grid, but completely overhaul its sizing mechanism by injecting Pretext's dynamic height calculations, creating a mathematically perfect, zero-whitespace masonry layout.

---

## 📋 Strict Architectural Requirements
* **Dynamic Masonry Layouts:** The Bento Grid cards must completely bypass standard CSS flexbox auto-stretching.
* **Mathematical Shrink-Wrapping:** Configure visual cards to receive explicit height calculations `style={{ height: calculatedHeight }}` derived directly from the Pretext engine calculations based on dynamic case study and stats text streams.
* **Responsive Layout Swapping:** Connect the container elements to a `ResizeObserver` to trigger mathematically clean recalculations in sub-millisecond cycles without triggering DOM reflows.

---

## 📋 Acceptance Criteria
- [ ] Integrate Aceternity's Bento Grid layout into the `app/page.tsx` dashboard area.
- [ ] GitHub API data (fetched via Server Components) seamlessly hydrates the client-side grid items.
- [ ] Each Bento Grid card dynamically accepts a `style={{ height: calculatedHeight }}` prop generated by the `usePretextLayout` hook based on the data payload.
- [ ] Implement Framer Motion `layout` props so cards smoothly reposition themselves if the data filters change (e.g., user toggles "Only show Rust repos").

---

## 🛠️ Step-by-Step Plan
1. **Component Integration:** Copy the Aceternity Bento Grid base layout. Strip out its static CSS flex-grow properties to prepare it for absolute mathematical heights.
2. **Data Hydration:** Pass the cached GitHub API statistics (from Issue #12) into the grid component.
3. **ResizeObserver Hookup:** Bind the Bento Grid container to the Pretext `ResizeObserver`. As the browser resizes, Pretext must recalculate the optimal text flow for the repository descriptions and output the exact pixel height for each card, triggering a fluid 60FPS Framer Motion layout transition.
